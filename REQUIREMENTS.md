# Adaptai requirements

Adaptai is a local-first Android app for running and cycling with one active, externally authored plan. The athlete imports and edits it or approves bounded Chat revisions.

| ID | Requirement | Acceptance case |
| --- | --- | --- |
| R-01 | Deliver a personal-use Android app with no multi-user account or hosted app-backend dependency. | AT-01: Install on Android, launch without an app account, and use a saved plan offline; inspect architecture for backend dependencies. |
| R-16 | Persist plan, event, completion, cached Garmin data, settings, guidance, and chats locally; recover gracefully from corrupt/incompatible state. | AT-16: Restart populated state and compare values; load corrupt/unsupported fixtures and verify useful recovery without crash or silent overwrite. |
| R-18 | Import/edit research and constraints as Markdown/plain text, persist edits, and preserve content on cancelled imports. | AT-18: Import both formats, edit, restart, then cancel import; verify content and persistence. |
| R-19 | Use OpenRouter for all LLM access with a securely stored OpenRouter API key and user-selectable model. | AT-19: Configure a key/model, switch models and restart; capture requests to verify the selected model and key, with no key in ordinary state. |
| R-21 | Include at most 20,000 characters each of research and constraints per request; notify of truncation and preserve full local originals. | AT-21: Submit above/below-limit documents; inspect payload lengths, notice, and stored originals. |
| R-22 | Request coaching/generation from the device through OpenRouter using the selected model; display responses or useful authentication/network/timeout/quota/malformed-response errors. | AT-22: Exercise OpenRouter for success, unavailable model, and each failure; verify feedback, cleared busy state, and unchanged active plan on failure. |
| R-23 | Make no provider request without a key; explain configuration. | AT-23: Attempt chat/generation with absent/blank keys; assert zero provider calls and Settings guidance. |
| R-24 | Instruct the coach not to diagnose injury and to recommend medical evaluation for concerning symptoms. | AT-24: Inspect OpenRouter request system instructions; display a pain-concern fixture without saving an unreviewed change. |
| R-25 | Retain the latest ten chat threads and their messages locally, with ability to resume them. | AT-25: Create eleven threads, restart, and verify newest ten; resume one and verify earlier messages and new reply persist. |
| R-26 | Authenticate the owner's non-MFA Garmin account through an isolated native adapter; report bad credentials or unavailable sessions. | AT-26: Verify real Android login plus bad-credential/no-session fixtures; show connected only on validated success. |
| R-27 | Securely store Garmin password/session metadata; keep password input blank after saving; empty input retains password and a new value replaces it. | AT-27: Save/reopen/save blank/replace; verify display and secure values without plaintext state/log leakage. |
| R-28 | Provide on-demand Garmin sync, last-success time, and cached offline data; background sync is not required. | AT-28: Sync then restart offline; verify cache/time and no scheduled background-sync dependency. |
| R-29 | Sync available run/ride ID, sport, name, start time, distance, duration, average HR, pace/speed, elevation, power, cadence, and lap data. | AT-29: Map full/partial run/ride fixtures; verify conversions, deduplication, sport display, and no fabricated optional values. |
| R-30 | Use available Garmin athlete data for baseline: history/volume, longest sessions, zones, fitness/load, and recovery where retrievable. Document supported fields; mark unavailable data unknown. | AT-30: Test full/partial fixtures and inspect planning context; compare supported-field inventory to real-account sync, verifying unknown fields stay unknown. |
| R-31 | Disconnect expired/unauthorized sessions, require reauthentication, report sync failures accurately, and preserve successful cached data. | AT-31: Simulate 401/403, network failure, and malformed data; verify status/errors, unchanged success timestamp, and retained cache. |
| R-33 | Export the displayed next seven days as Markdown, PDF, and iCalendar using actual dates and metric values. | AT-33: Export December/January fixtures; compare text/PDF to view and import .ics into a calendar to check dates. |
| R-34 | Use safe event-derived filenames, escaped PDF HTML/calendar text, and stable unique calendar IDs. | AT-34: Export path characters, HTML, commas, semicolons, and newlines; verify safe paths, literal text, valid calendar, and stable distinct IDs. |
| R-35 | Use device sharing when available; otherwise provide a usable save/export fallback or actionable explanation. | AT-35: Share each format on Android; simulate unavailable sharing and verify fallback. |
| R-39 | Use English, metric units, and minimalist dark styling with readable text and clear error/loading/disabled states. | AT-39: Review screens/proposals on small/large Android displays; verify English, km/metres, pace per km, cycling km/h, dark styling, and legible feedback. |
| R-40 | Keep data local except explicit Garmin communication and selected context sent through OpenRouter to the selected downstream model provider; never send Garmin secrets to AI. | AT-40: Capture sync/coaching/offline/backup traffic; verify destinations and no Garmin secret sentinels in provider requests. |
| R-41 | Explain context sharing through OpenRouter and its selected downstream model provider; exclude secrets from ordinary state, logs, exports, and backups; encrypt API keys/passwords/session metadata. | AT-41: Review disclosure; inspect state/logs/outputs with secret sentinels; verify Android secure storage for each secret. |
| R-42 | Pass strict TypeScript checking. | AT-42: Run documented typecheck command on a clean checkout; require strict configuration and zero exit code. |
| R-44 | Document reproducible Android builds independent of Ona: prerequisites, commands, signing, and output artifacts/adaptai-release.apk. | AT-44: Follow README in a clean non-Ona environment; build and verify APK at the stated path. |
| R-45 | Document testing-only signing if used and verify installation/upgrades preserving data on the owner's device. | AT-45: Compare APK signing to documentation; install, populate data, and upgrade with same signing identity; verify preserved plan/chats/settings. |
| R-46 | Offer responsive browser planning/chat/review/backup on phones, tablets, and desktops. Disclose browser storage/security and unsupported native features; no implied cross-device sync. | AT-46: Exercise core flows at representative browser sizes; verify native-feature fallback and documented browser credential policy. |
| R-47 | Explicitly push accepted run/ride workouts with correct sport, structured steps/targets/durations, and dates to Garmin; skip rest. | AT-47: Push run/ride interval/rest fixtures; inspect payloads and real-account entries, including a 2h 30m session. |
| R-48 | Report per-workout push failures and retry without duplicating successes; accepting a plan alone never pushes it. | AT-48: Fail mid-push and retry; verify recorded remote IDs prevent duplicate successes, errors remain visible, and acceptance makes no push request. |
| R-49 | Fetch and retain at most the last 50 Garmin activities, displaying supported running/cycling records. Trim older cached history on upgrade without losing other state. | AT-49: Sync 60 out-of-order fixtures; verify a request limit of 50, the latest 50 retained, and preservation of chats/settings during legacy-state loading. |
| R-50 | Fetch running/cycling VO₂ max, cycling FTP and FTP/kg (W/kg), and configured heart-rate zones during on-demand sync; display them in Settings with units and fetch timestamps. Missing data is unavailable; failed optional refreshes retain cached values with warnings while activity sync succeeds. | AT-50: Map full, partial, empty, malformed, and failed endpoint fixtures; verify precise VO₂, cycling identity, valid W/kg conversion, zone ranges in bpm, timestamps, cache retention, Settings rendering, and coaching context; compare with the owner's Garmin data on Android. |
| R-51 | Render Markdown chat messages with headings, emphasis, lists, quotes, code, tables, and safe links. Raw HTML remains text; remote images do not load automatically. | AT-51: Render representative Markdown and inspect formatting; activate an HTTPS link; verify script/unsafe URI fixtures cannot execute and images remain descriptive text. Recheck on Android. |
| R-66 | Jump to the top of the latest coach message when opening/switching a conversation or receiving a reply, retaining top alignment when the keyboard changes available height. Allow manual scrolling afterward. | AT-66: Verify latest, rather than earlier, assistant layout coordinates drive scrolling; switch threads and receive a new reply. Check a short and long reply on Android with keyboard open/closed, then manually read earlier messages without forced jumps. |
| R-67 | Offer Claude Sonnet 4.6, Claude Haiku 4.5 and Gemini 2.5 Flash in a model dropdown while retaining editable custom OpenRouter identifiers. Apply selection only on Save settings, preserving it across restart and using it for chat/planning. | AT-67: Select each preset, verify its exact provider ID and no automatic save, then save/restart. Type/save a custom ID and verify it is retained; inspect chat/plan requests for the chosen model. |
| R-68 | Use the existing Adaptai teal A as the Android home-screen/app-list icon, with a dark background, round/adaptive support and a monochrome layer for themed launchers. Keep the Adaptai label, package identity and upgrade signing. | AT-68: Prebuild and inspect all five launcher densities, adaptive foreground/background/monochrome references and safe artwork bounds. Inspect the built APK's icon resources and label, compare packaged images to generated assets, and verify version/signature for an in-place upgrade. Install over the existing phone app and check home/all-apps screens with normal and themed icons. |
| R-70 | Download a Markdown template. Require a plan title, then at least one training goal or event goal directly before the schedule. Allow both. Settings has no standalone goal import. Use YYYY-MM-DD headings, multiple sessions per date and free-form notes. Rest dates may be omitted. | AT-70: Download and import the template. Test training-only, event-only and dual goals, two same-day sessions, notes, an omitted rest date, missing goals, missing title and invalid dates. Verify Settings has no standalone goal import. |
| R-71 | Export the entire active plan as importable Markdown including binary completion and optional note and integer exertion 1–10. Successful import atomically replaces schedule and history from the file. Missing history defaults to incomplete and blank optional fields. Duplicate titles are valid. | AT-71: Round-trip duplicate titles and mixed completion, then reimport changed and omitted history. Verify the resulting persisted state equals the file. |
| R-72 | Explain invalid Markdown with actionable corrections. Invalid or cancelled import preserves the active plan. | AT-72: Try invalid date, missing workout measure, invalid effort and cancelled picker against a populated plan. Verify feedback and unchanged storage. |
| R-73 | Show today and the next six local dates with English weekdays, with history collapsed by default. Below the entire plan summary, provide an expandable history of past planned workouts and cached Garmin activities dated within the plan. Show both newest first with completion readable on planned workouts. Show sport and type first, followed by title, description, and duration and distance where present. Require at least one measure with explicit units. | AT-73: Freeze local today across a month boundary. Verify seven date groups, hidden history by default, and past planned workouts and cached Garmin activities visible after expanding history. Verify Run · Easy, ride, duration-only, distance-only and both-measure layouts. |
| R-74 | Complete or uncomplete today’s workouts manually. Partly done counts as complete. Optional note describes actual work and optional effort is an integer from 1–10. Use local dates and recheck on save. | AT-74: Mark a partly performed session complete with note and effort, restart and verify. Reject 0, 11, fractions and a save after midnight. |
| R-75 | Allow direct prescription edits and moves of incomplete workouts today or later. Swap by selecting the second eligible workout in the schedule. Allow moving an unstarted incomplete past workout to a future date with its prescription intact. Past prescriptions are read-only and completed sessions cannot move. | AT-75: Edit, move and swap eligible workouts. Reject completed moves and past prescription edits. Move an unstarted past workout forward and compare every prescription field. |
| R-76 | Chat can propose adding, deleting, moving or modifying sessions today or later. Existing targets must be incomplete. All affected dates must fit one seven-day window, including both dates of a move. Use active-plan workouts including past examples. Copies begin incomplete with blank history. Apply configured scheduling rules and coach guidance to proposals. | AT-76: Exercise all operations, day-seven and day-eight boundaries, both move dates, past/completed targets, copy a completed past example and exercise a rule violation. |
| R-77 | Preview Chat diffs and validation errors. Require approval to apply valid changes. Flag a proposal as stale after any active-plan change and require regeneration. Use the most recent synced Garmin activity in upcoming-workout proposals and preserve lookup on request. Include plan goals, guidance and relevant chat/athlete context. | AT-77: Reject and approve proposals, inspect invalid diffs, edit and reimport during separate reviews, and verify stale proposals cannot apply. Seed out-of-order Garmin activities and verify newest context for lookup and proposals. |
| R-78 | Provide Plan, Chat and Settings navigation, with Sync Activities in Plan and Settings. Keep Garmin credentials, model and guidance controls in Settings. Preserve compact branding and headings. | AT-78: Check all three tabs and both sync controls, save Settings, and inspect narrow and desktop layouts and Android large text. |
| R-79 | Export cached Garmin activities in CSV and Markdown from Settings. Include activity date, sport, duration, distance and average HR where available. Default to all cached activities. | AT-79: Export mixed run and ride fixtures in both formats. Check dates, units, escaped fields and missing HR. |
| R-80 | Optionally show same-day Garmin activities beside scheduled workouts. Completion remains manual. | AT-80: If implemented, sync multiple activities on a shared date and verify visibility and unchanged completion. |
| R-81 | Show busy feedback and prevent duplicate sync, import, export and proposal approval. | AT-81: Repeat each delayed action and verify one operation and recovery after success or failure. |
| R-82 | Package bundled research and constraints for Settings. Handle malformed or truncated provider responses with useful feedback and at most one incomplete-response retry. | AT-82: Load packaged guidance on Android, test missing assets, and exercise truncated and complete provider responses. |
| R-83 | Maintain acceptance traceability and automated coverage where practical for all active requirements and stories. | AT-83: Execute the traceability matrix, recording automated and device results by acceptance ID. |

R-46 through R-51 and R-80 are optional. Gaps in numbering preserve historical acceptance IDs. See [user stories](USER_STORIES.md) and [development gates](DEVELOPMENT_PLAN.md).
